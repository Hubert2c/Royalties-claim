Why an open API?

Following the network-centric model of India's Open Network for Digital Commerce (ONDC), the Government owns the registry, the tariff rules and the audit trail, and publishes standard APIs so that other systems can plug in: broadcast playout software, radio-monitoring services, ticketing apps, telecoms and streaming services. They report usage in one standard format instead of each building a separate deal.

Authentication

Send an API key in the X-API-Key header.

  • Licensee keys — created by a licensee in the Licensee portal (API keys). Reports are recorded for that licensee.
  • Monitor keys — issued by the Government in the console (Settings & API keys) to a broadcast-monitoring service. Each report must include station_id (the station's licensee ID).

Base URL: http://localhost:3001/api/open/v1 (local prototype).

POST /usage — report plays, set lists, cue sheets

curl -X POST http://localhost:3001/api/open/v1/usage \
  -H "X-API-Key: rh_live_..." -H "Content-Type: application/json" \
  -d '{
    "source": "play_log",
    "events": [
      { "played_at": "2026-10-24T08:15:00Z", "title": "Midnight Echo",
        "artist": "Munezero Hubert", "isrc": "RWA012600001", "duration_sec": 210 }
    ]
  }'

source: play_log, set_list, cue_sheet or ddex. Up to 5,000 events per request. Each event is matched by ISRC, then by title + artist. Unmatched events go to the public unclaimed list.

Response: { saved, matched, unmatched, errors, events: [{ id, matched, recording_id, title }] }

POST /fingerprint-matches — report airplay by audio fingerprint

A monitor records a few seconds of a station's stream, runs the open-source Chromaprint tool fpcalc -raw clip.wav, and sends the numbers after FINGERPRINT=. The platform compares them with every registered recording (bit error rate) and records a play if at least 65% of bits agree. Register each song with fpcalc -raw -length 600 song.mp3 so the whole song is fingerprinted, not just the first two minutes.

curl -X POST http://localhost:3001/api/open/v1/fingerprint-matches \
  -H "X-API-Key: rh_live_..." -H "Content-Type: application/json" \
  -d '{ "station_id": "LIC-RADIO", "played_at": "2026-10-24T08:15:00Z",
        "duration_sec": 210, "fingerprint": "123456789,987654321,..." }'

Response: { usage_id, matched, recording_id, title, confidence }

A ready-made helper script is included: node tools/monitor-report.js clip.wav LIC-RADIO (needs fpcalc installed and the ROYALTY_HUB_API_KEY environment variable).

GET /catalogue — registered recordings

curl http://localhost:3001/api/open/v1/catalogue -H "X-API-Key: rh_live_..."

Returns { recordings: [{ id, title, performer, isrc, duration_sec, iswc }] } so client systems can attach ISRCs before reporting.

Public endpoints (no key)

  • GET /api/public/summary — collections, distributions, admin fees, held money, approved runs
  • GET /api/public/unclaimed — unmatched plays
  • GET /api/public/clearance/{code} — is a clearance code valid?

Every API call that changes data is written to the tamper-evident audit log.
